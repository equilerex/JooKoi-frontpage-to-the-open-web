Raw notes on access problems, missing tooling, confusion, paper-trail trouble and inefficiency red flags hit during agent sessions. Input for later workflow review. Append dated bullets, newest session at the bottom. Tags: `[access]` `[tooling]` `[confusion]` `[paper-trail]` `[inefficiency]` `[instructions]`.

## 2026-09-16 — Phase 2 execution, all 18 tasks (design system)

The Phase 2 run cost far more than it should have: too many tokens, too much wall-clock, and the same class of misunderstanding more than once. The four entries below are the causes, not the symptoms.

- `[inefficiency]` **Token cost.** Every task dispatched a fresh subagent that re-read `AGENTS.md`, the Phase 2 plan, the mockups and the ledger from scratch. `progress.md` grew to about 2,000 lines and was read whole by the controller and by most subagents, repeatedly. One 2,000-line file read once per task is the largest avoidable cost in the run. Fix: `progress.md` is append-only short entries and is read by `grep`, never end to end. Decisions go in an ADR, never in the ledger, which is how it reached 2,000 lines.
- `[inefficiency]` **Runtime.** The plan wrote per-task gates into its steps (`pnpm run build`, lint and prettier by hand) that `AGENTS.md` had already defined once in its Iteration loop. Each task then paid for a production build that CI owns and that competes with the dev server for `.angular/cache`. The root cause is a second copy of the gates, not a careless agent. Fix landed during this phase: `AGENTS.md` now states that gates are defined once and must not be restated in a brief, a dispatch, a plan or a checklist; the plan's stale gate lines were corrected; and `scripts/deny-build.mjs` plus `scripts/lint-changed.mjs` (Stop hook, changed files only) make the second mechanism unreachable rather than merely discouraged.
- `[inefficiency]` The run's own cost forced a context compaction mid-task, which is the failure the global context-hygiene rule warns about. Compacting mid-task means the resumed agent re-reads the architecture doc and the ledger to rebuild what it already knew, which is more tokens again. Fix: the two entries above, plus compacting at a task boundary rather than inside one.
- `[confusion]` **Misunderstandings, all the same shape.** Briefs asserted things about the tree that were not true, and each cost a round trip: a "Phase 1 class map" to amend (superseded by decision 012, to be deleted rather than edited), the `--png-` preset prefix called fabricated when `app.config.ts` sets `prefix: 'png'` deliberately, the design-system sub-groups approximated as `layout` and `overlays` when the directory holds nine groups, and a `record-grid.harness.ts` implied to exist when decision 008 makes a harness optional. Fix: a brief may assert a fact about the current tree only with a file path beside it, and must otherwise mark the claim as an assumption to verify before acting on it.
- `[instructions]` The plan's boundary proof used a `RouterLink` import, which could never fire: the generated rule matches folder names under `src/app/`, not package names. Corrected to an `app-shell` import and verified firing in Task 18.
- `[tooling]` The paper-trail `backlog` script drops `"` and `>` from its body argument when invoked from PowerShell, truncating an entry mid-sentence (`<details class="drawer panel">` lost everything from the quote onward). Caught and repaired by hand. Fix the script, or keep angle brackets out of backlog bodies.
- `[paper-trail]` The ledger carried two rulings that contradicted each other: R1 declared the `--png-` prefix fabricated, and a later entry corrected it. A log read as a decision record will contradict itself, and a reader will believe the first ruling they find. Rulings belong in a dated ADR, or they need to be superseded in place rather than appended further down.
