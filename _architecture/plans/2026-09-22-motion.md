# Motion design system audit and roadmap

Session: 2026-09-22. Status: Audited; implementation not started.

## Context

The application has a deliberately restrained visual language, but its current motion layer is not perceptible enough to make navigation or state changes feel connected. The existing route and library animations are technically present yet use small offsets, generic `ease`, and in one case are explicitly disabled when View Transitions are available. They should be treated as a superseded prototype, not as a foundation to extend.

The target is a functional motion system for Angular 22, plain CSS, signals, router View Transitions, and PrimeNG overlays. Motion should explain a state change, preserve spatial relationships, confirm input, or prevent a teleport. It should not turn the retro HUD decoration into constant movement or animate data the user is reading.

## Rejected candidates

- `src/app/app-shell/horizon-backdrop/horizon-backdrop.component.css:46-75` — continuous floor scrolling. Rejected as a user-facing enhancement: it is decorative, always running, and adds visual noise/perf cost to a utility users may keep open for long periods. Keep it static under reduced motion; do not intensify it.
- `src/app/shared/design-system/indicators/status-light/status-light.component.css:32-49` — blinking LEDs. Rejected for expansion: status indication is already covered by the existing optional blink, and more persistent blinking would compete with content. Preserve the current restrained behavior.
- `src/app/shared/design-system/data-display/record-grid` — row entrance stagger or animated sorting. Rejected because the grid is functional data and can update frequently; moving rows hinders scanning. Use stable content and only animate a state bridge around an intentional, committed update if needed.
- `src/app/app-shell/app-shell-layout/app-shell-layout.component.ts:66-86` — animating shell width on every navigation. Rejected as a default: width/layout animation is not transform-only and risks reflow; if the library width change remains necessary, measure it as a separate shell transition and keep it out of the initial paint.

## Before / after motion language

| Before                                                                            | After                                                                                            | Why                                                                                                                     |
| --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| `animation: app-main-in 240ms ease` with `translateY(0.5rem)`                     | `transform` + `opacity` under `180–240ms var(--ease-out)` with an explicit route recipe          | The current motion is too quiet and generic; the replacement gives immediate movement and a clear spatial relationship. |
| Folder fallback animation disabled under `@supports (view-transition-name: none)` | One named owner: View Transition when active, CSS fallback otherwise, both using the same values | Prevents the “present in code, absent in experience” failure.                                                           |
| Conditional funnel tiers and filters appear instantly                             | Enter/exit `opacity` + `translateY(4–6px)`, 120–220ms                                            | Bridges state changes without animating the data itself.                                                                |
| `ease`/implicit browser easing across unrelated components                        | `--ease-out: cubic-bezier(0.23, 1, 0.32, 1)` plus documented semantic recipes                    | Gives the interface one recognizable response curve.                                                                    |
| Hover-only visual changes apply wherever the pointer lands                        | `@media (hover: hover) and (pointer: fine)` around hover motion                                  | Avoids sticky/false hover on touch.                                                                                     |

## Build order

1. Replace the failed route/library prototype with a single motion contract: semantic easing tokens, exact duration roles, reduced-motion rules, and an ownership rule for View Transition versus CSS fallback. This is the system slice, not a visual polish pass.
2. Implement the search funnel and active-filter transitions. These are the clearest current teleporting states and can be judged without inventing new product behavior.
3. Implement the library reader entry and document-to-document behavior, preserving the opaque reader frame and retained-content loading strategy.
4. Normalize press feedback across the existing interactive design-system controls, keeping hardware keys as the physical reference and avoiding animation on keyboard/high-frequency actions.
5. Run a live feel-check at 390px and 1440px, with normal speed, reduced motion, and slow-motion inspection. Finish the UI slice with the existing `ux:smoke` gate and add scenarios only if a new route/state surface is shipped.

## Scope boundaries

This plan does not add a motion library, spring physics, continuous decorative motion, animated data grids, page-wide stagger choreography, or a new loading skeleton. It does not change product behavior or the existing retained-content loading strategy. Any new overlay/disclosure component is a separate task and belongs in the backlog before implementation.

## Implementation deviations

The document reader remains CSS-only. Its routed child is remounted between documents, so pure CSS cannot interpolate two intrinsic `auto` heights or delay the outgoing node after Angular removes it. The implementation uses the fixed paper baseline as the minimum landing height, preventing the short empty-slot collapse without JavaScript measurement. The existing UX smoke scenario can still miss the new document H1 during the resource/remount window (`doc-to-doc`, 1/12 samples on repeated runs); that is a separate content-loading boundary, not a reader-height transition failure. The cold-search long-task history check also remains an intermittent baseline regression and was not altered by this motion work.

The search filtering correction keeps the results panel mounted while query parameters change. Row-level enter/leave transitions were evaluated and discarded: attaching `animate.leave` to hundreds of collection rows caused severe frame drops, DOM retention leaks, and layout freezes on filter changes. `RecordGridComponent` remains a plain table tracked by `$index` per Decision 032. Filtering state is managed with writable signals in `SearchPage` and synchronised silently to the browser URL via `Location.replaceState()`, preventing Angular router navigations, unwanted View Transitions, and destructive scroll-to-top resets while maintaining shareable/refreshable URLs. Keyword filtering updates live synchronously in memory while URL replacement is debounced.
