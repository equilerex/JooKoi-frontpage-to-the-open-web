Context windows

A model reads a fixed number of tokens per request. Everything it knows about your task has to fit inside that budget: the system prompt, the conversation so far, tool output and the files you pasted. The limit is set per model, for example 200k tokens.

A bigger window does not mean better recall. Details in the middle of a long context are easier to miss than details near the start or end.

What fills the window

  • Instructions that load on every turn, such as AGENTS.md
  • The running conversation, including the model's own replies
  • Tool results, which are often the largest share

Measuring it

Most SDKs return usage on each response. Log it before optimising anything.

const res = await client.messages.create({ model, messages, max_tokens: 1024 });
console.log(res.usage.input_tokens, res.usage.output_tokens);

Rough budgets

Content Typical size Notes
One page of prose ~500 tokens English, plain text
300-line source file ~3,000 tokens Varies with symbol density
Verbose test output 10,000+ tokens Pipe or trim before reading

Keeping it lean

  1. Search before reading whole files.
  2. Summarise finished work instead of carrying raw output forward.
  3. Start a fresh session when the task changes.
